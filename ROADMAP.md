# Roadmap

## Available: manifest prototype with four export adapters

- Explicit sample relationships, local JSON result links and result-file hashes.
- Structural checks, duplicate-source rejection and a portable, static HTML report.
- Four version-aware adapters, one per source-tool export:
  - LIV: `analysis.json` (schema 0.1.0, CW) — fit interval, threshold, slope, provenance.
  - PL: `*_PL_metrics.json` (schema 1) — Presentation semantics kept separate from Raw Peak / fit widths.
  - Beam: `result_summary.json` — angles, waist diameters, scan status, calibration, fit model.
  - Spectral: `spectral-analysis.json` (schema 0.1.0) — spacing-rule semantics, per-threshold comb counts.
- Condition merging: manifest supplements unknowns; source values win; conflicts are errors.
- Synthetic fixtures generated by the real tools (exporters, CLIs and viewer functions).

## Next: integration depth

- Retain and verify raw-input hashes when the original CSVs are available.
- Cross-check adapted values against the source payload in regression tests.
- Extend the beam adapter when the export gains a top-level schema version.
- Condition-aware comparison views: flag non-comparable metrics (a.u. vs dBm,
  different widths semantics, CW vs pulsed) instead of listing them side by side.
- Build a fuller synthetic integration case: wafer with multiple devices,
  growth/process records, missing-condition diagnostics.

## Later: research workflow

- Growth/process records, batch import and condition-aware device comparison.
- Analysis history and explicit raw-data availability.
- Traceable feature datasets and predictive baselines when suitable data exists.

These are future milestones. The current scaffold does not claim those capabilities.
